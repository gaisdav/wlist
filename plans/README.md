# План разработки Social Wishlist

Этот каталог содержит пошаговый план разработки сервиса.

- Концепция — в [`../concept.md`](../concept.md).
- Архитектура — в [`../docs/architecture.md`](../docs/architecture.md).

## Принципы

- **MVP-first.** Сначала выпускаем минимально жизнеспособный продукт (Telegram Mini App с CRUD желаний и слотами), потом наращиваем фичи.
- **Платформа сейчас:** только Telegram Mini App. Веб-сайт и React Native — позже.
- **Архитектура сразу под монорепо**, чтобы безболезненно расширяться на другие платформы. Бизнес-логика выносится в переиспользуемые пакеты.
- **Auth в MVP:** только Telegram (TMA initData), без email/phone.
- **Realtime в MVP:** не используется, достаточно refetch после действий.
- **Telegram-бот в MVP:** только как launcher Mini App, без логики уведомлений.

## Принятые технические решения

| Область                  | Решение                                                            |
| ------------------------ | ------------------------------------------------------------------ |
| Моно-репо инструмент     | **pnpm workspaces**                                                |
| Frontend стек            | React + TypeScript (strict)                                        |
| Серверный стек           | Supabase + Edge Functions (отдельных backend-сервисов в MVP нет)   |
| Локальная БД-разработка  | Гибрид: миграции пишем локально, применяем к remote dev-проекту    |
| Server state             | **TanStack Query**                                                 |
| Формы                    | **React Hook Form + Zod**                                          |
| Runtime-валидация        | **Zod** (формы, ответы API, входы Edge Functions)                  |
| Роутинг                  | Свой на каждой платформе; маршруты описываем декларативно в `core` |
| UI / стилизация          | **Tailwind CSS** + точечные CSS Modules для сложной графики; компоненты пишем сами (без UI-библиотеки) |
| Дизайн-токены            | Plain TS в `packages/core/tokens` — единый источник для всех платформ                                  |
| Варианты компонентов     | **`tailwind-variants`** (или `cva`) + `clsx`                       |
| Структура `core`         | **Layer-based**: `entities/`, `services/`, `hooks/`, `types/`, `tokens/` |
| Хостинг TMA              | **Vercel**                                                         |
| Локализация              | **English only** в MVP (i18n-инфраструктуру закладываем сразу)     |
| i18n библиотека          | **`i18next` + `react-i18next`**, словари в `@wlist/core/i18n`      |
| Маршрутизация в TMA      | Свой лёгкий роутер на History API + интеграция с Telegram BackButton; `wouter` — резерв |
| Optimistic updates       | По умолчанию для каждой мутации с очевидным UX-выигрышем; в MVP — минимум |
| Тестирование RLS         | До релиза — ручное; автоматический suite — после первой беты       |
| Генерация типов из БД    | `supabase gen types` → `database.types.ts` + **`supazod`** → `database.zod.ts`. Доменные entities — `.transform()` поверх row-схем |
| Структура `core/hooks/`  | По доменам (`hooks/wishes/`, `hooks/slots/`, …); `entities/` и `services/` — плоско |
| Sentry / аналитика       | В MVP не подключаем, добавим post-MVP                              |
| Realtime                 | В MVP не используем (см. этап 11)                                  |
| Тестирование             | **Vitest** unit для security-critical и pure-функций по факту фичи; **Playwright** smoke-E2E перед релизом MVP; полный RLS test suite — после беты. Подробнее: `docs/architecture.md` §16 |
| Дефолтная валюта         | USD (EN-локализация)                                               |

## Структура файла этапа

Каждый этап описан по единому шаблону:

1. **Цель** — что хотим получить на выходе.
2. **Зависимости** — какие этапы должны быть готовы.
3. **Скоуп** — что входит.
4. **Вне скоупа** — что осознанно НЕ делаем на этом этапе.
5. **Ключевые решения** — важные технические/продуктовые выборы.
6. **Чек-лист задач** — конкретные подзадачи.
7. **Definition of Done** — критерии готовности.
8. **Открытые вопросы** — что ещё нужно решить.
