# Этап 10. Полноценный Telegram-бот: уведомления и секретные чаты

> **Статус: ⬜ не начат.** PR-разбивка и ключевые решения зафиксированы 2026-06-29
> (после завершения этапов 03/06/07 и приватности 08). Делать строго по PR —
> этап большой, одним куском не влезает.

## Цель

Развернуть бота из «launcher Mini App» в канал коммуникации: уведомления о
событиях вокруг желаний, напоминания о праздниках, упоминания в комментариях и
(по запросу) групповые чаты.

## Зависимости

- Этап 03 (слоты) — уведомления «слот освободился» / «собрано».
- Этап 06 (комментарии) — упоминания.
- Этап 07 (события) — напоминания о праздниках.
- Этап 08 (приватность) — **критично**: ни одно уведомление не должно раскрывать
  то, что скрывает RLS. Получателей считаем через `can_view_wish`.

## Архитектура (зафиксировано)

- **Бот = Edge Function `telegram-bot`** (Deno), приём вебхуков от Telegram. Тот
  же паттерн, что `auth-telegram` (`_shared/cors.ts`, `_lib/`, `deno.json`,
  контракт + тесты). Никакого long-running worker в MVP бота.
- **Доставка через outbox, не из триггеров напрямую.** Доменные события пишут
  строку в `public.notification_outbox` (через `SECURITY DEFINER` триггеры/функции).
  Отдельный «drainer» (Edge Function, запускается `pg_cron` + `pg_net` раз в
  минуту) забирает pending-строки, шлёт `sendMessage`, проставляет статус, ретраит
  с backoff. Сбой Telegram API НЕ ломает пользовательский запрос.
- **Секреты:** `TG_BOT_TOKEN` уже в Function Secrets (используется `auth-telegram`).
  Вебхук защищаем `secret_token` (заголовок `X-Telegram-Bot-Api-Secret-Token`).
- **Приватность уведомлений — инвариант, не фича.** «Кто-то забронировал твой
  слот» НЕ шлём (автор не должен знать — см. §2). Текст сообщений не должен
  содержать данные, скрытые от получателя; получателей вычисляем через
  `can_view_wish(recipient, wish)`.

## Виды уведомлений

| Триггер | Получатель | Приватность |
| --- | --- | --- |
| Кто-то забронировал слот моего желания | — | **НЕ шлём** (нарушит скрытие от автора) |
| Слот, который ты держал, освободился (чужая отмена) | держатели активных слотов того же желания | им желание уже видимо |
| Желание полностью собрано (`active = cap`) | держатели слотов | видимо |
| Через N дней день рождения друга | подписчики, кому видимо событие | `event` сейчас публичны |
| Тебя упомянули в комментарии (`@username`) | упомянутый, если ему видна ветка | через видимость ветки + `can_view_wish` |
| Новый подписчик | автор | — |

Каждый тип выключается в настройках (`notification_settings`).

## План по PR

### PR A — bot webhook + `tg_private_chat_id` (инфраструктура)
- Миграция: `profiles.tg_private_chat_id bigint nullable`.
- Edge Function `telegram-bot`: верификация `secret_token`, разбор update,
  команды `/start`, `/start <payload>` (deep-link в Mini App), `/help`. На `/start`
  — upsert `tg_private_chat_id` по `telegram_id` (service-role).
- `_lib` + unit-тесты на разбор update и роутинг команд (Node/Deno, как у
  `auth-telegram`).
- Регистрация вебхука — ручной шаг (документировать в README функции), не код.

### PR B — outbox + drainer (доставка)
- Миграция: `public.notification_outbox` (`id`, `recipient_user_id`,
  `kind`, `payload jsonb`, `status` enum `pending|sent|failed`, `attempts`,
  `created_at`, `sent_at`, `last_error`). RLS: клиент **не** читает/пишет; только
  `SECURITY DEFINER`/service-role.
- Edge Function `notifications-drain`: берёт pending (батч, `for update skip
  locked`), резолвит `tg_private_chat_id`, шлёт `sendMessage`, ставит `sent`/`failed`+
  `attempts++`, backoff. Идемпотентность по строке.
- `pg_cron` + `pg_net`: дёргать drainer раз в минуту (или по триггеру через
  `pg_net` сразу после вставки — решить в PR B).
- Шаблоны текста — чистые функции в `core/lib` (локализуемые), без PII сверх
  нужного.

### PR C — настройки уведомлений
- Миграция: `public.notification_settings` (`user_id` PK + булевы флаги из §
  «Виды», default true). RLS: владелец читает/пишет своё.
- API `ApiClient.notifications` (get/update) + core hooks + queryKeys.
- UI: экран «Уведомления» в профиле (`/me/notifications`), тумблеры.
- Drainer/триггеры уважают флаги: не ставим в outbox то, что выключено (проверка
  при enqueue).

### PR D — триггеры-источники: slot_freed, wish_collected, new_follower
- `SECURITY DEFINER` функции/триггеры на `wish_slots` (cancel → freed; insert →
  проверка `active = cap` → collected) и `follows` (insert → new_follower).
- Enqueue в outbox с учётом `notification_settings` и приватности (получатели —
  держатели слотов / автор; НЕ автор для freed).

### PR E — события: напоминания (расширение этапа 07)
- `pg_cron`: ежедневная задача — найти события через N дней (учёт
  `is_recurring_yearly`), для подписчиков владельца enqueue `event_reminder`.
- Порог N (14 дней?) — в константу `core/lib`.

### PR F — упоминания в комментариях (расширение этапа 06)
- TMA: парсинг `@username` в теле комментария → кликабельная ссылка на профиль.
- Резолв `@username` → `profiles` (по `username`); enqueue `mention` упомянутому,
  если ему видна ветка/желание; учёт `notification_settings.mention`.

### PR G — секретные групповые чаты (по запросу)
- Миграция: `wishes.tg_chat_id bigint nullable`.
- **Реалистичный поток (Bot API не создаёт группы):** участник создаёт группу
  вручную → добавляет бота → бот по своей команде регистрирует `chat_id` в
  `wishes.tg_chat_id` → дальше шлёт апдейты в группу. UserBot НЕ используем (ToS-риск).
- TMA: кнопка «Открыть обсуждение в Telegram» — только если `tg_chat_id` задан.

### PR H — аналитика и мониторинг
- Лог доставки (есть в outbox: status/attempts/last_error).
- Sentry на webhook/drainer ошибки; алерт на рост 4xx/5xx от Telegram.

## Definition of Done

- Все типы уведомлений (кроме намеренно исключённого «забронировали твой слот»)
  ставятся в outbox, доставляются и логируются; выключаются в настройках.
- Бот обрабатывает `/start`, deep-link payload, `/help`, `/notifications`.
- Упоминания: кликабельные `@username` в TMA + доставка уведомления.
- Ни одно уведомление не раскрывает скрытое RLS (проверка на этапе ревью PR D/E/F).

## Ключевые решения

- **Outbox + drainer**, не прямые отправки из триггеров.
- **Уведомления по умолчанию включены, легко выключаются.**
- **Групповые чаты — «по запросу» + ручное добавление бота**, без UserBot.
- **Приватность уведомлений = инвариант**, считаем получателей через `can_view_wish`.

## Открытые вопросы

- Дайджест («1 раз в день») vs мгновенно — для шумных типов (события). По
  умолчанию мгновенно; дайджест — возможный backlog.
- Локализация уведомлений по `profiles.language_code` (сейчас только en).
- Порог напоминания о событии (N дней) и поведение для `is_recurring_yearly`.
- `pg_cron`/`pg_net` доступность на текущем Supabase-плане — проверить до PR B.
