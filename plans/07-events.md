# Этап 07. События и категории

## Цель

Дать пользователям возможность группировать желания по событиям (День рождения, Новый год, 8 марта…), а подписчикам — получать напоминания о приближающихся событиях друзей.

## Зависимости

- Этап 05 (соц-функции — лента и подписки нужны для уведомлений).

## Скоуп

### 1. Модель данных

Таблица `public.events`:

- `id` (`uuid`, PK)
- `owner_id` (`uuid`, FK → `profiles.id`)
- `title` (`text`) — например, «Мой День рождения»
- `kind` (`enum`: `birthday` | `new_year` | `march8` | `february23` | `custom`)
- `event_date` (`date`)
- `is_recurring_yearly` (`boolean`, default true)
- `is_archived` (`boolean`, default false)
- `created_at`, `updated_at`

Таблица связи `public.event_wishes`:

- `event_id` (`uuid`)
- `wish_id` (`uuid`)
- `position` (`int`)
- PK: `(event_id, wish_id)`

Желание может относиться к нескольким событиям одновременно.

### 2. RLS

- `events`:
  - **SELECT:** все авторизованные (с учётом приватности из этапа 08).
  - **INSERT/UPDATE/DELETE:** только владелец.
- `event_wishes`: владелец события == владелец желания.

### 3. Уведомления

- При создании события — добавить запись в `feed_events` («@user готовится к Дню рождения 12 апреля»).
- За **2 недели** до даты события (учитывая `is_recurring_yearly`) — рассылка подписчикам:
  - в MVP этого этапа — запись в `feed_events` с типом `event_reminder`;
  - полноценная рассылка через Telegram-бота — в этапе 10.
- Запланированная рассылка реализуется через `pg_cron` + Edge Function (или внешний планировщик).

### 4. UI

- На профиле — секция «События» (список карточек по дате).
- Открытие события — список привязанных желаний (фактически tematический подвишлист).
- Создание события: title, kind (выбор иконки), дата, recurring.
- При создании/редактировании желания — мультиселект «привязать к событиям».
- На главной/в ленте — блок «Скоро праздники у друзей» (события подписок в ближайшие 30 дней).

## Вне скоупа

- Telegram-уведомления (этап 10).
- Синхронизация с системными календарями (backlog в этапе 13).
- Авто-предложение события «День рождения» по дате из Telegram-профиля (Telegram её не отдаёт API → backlog).

## Ключевые решения

- **Recurring события — по дате, без времени.** Праздник = весь день.
- **`pg_cron` + Edge Function** для запланированных рассылок — нативно в Supabase, без внешней инфраструктуры.
- **Привязка желаний к событиям многие-ко-многим** — одно желание может быть и на ДР, и на НГ.

## Definition of Done

- Можно создать событие, привязать к нему желания, открыть как отдельный список.
- В ленте появляется напоминание за 2 недели.
- Recurring-события автоматически «переходят» на следующий год после прошедшей даты.

## Открытые вопросы

- Шаблонные события (Новый год, 8 марта) — авто-создавать всем при онбординге, или предлагать?
- Если событие удалено, что делать с привязанными желаниями? (Скорее всего — оставить, разорвав связь.)
- Нужен ли календарь-вью с месяцами или достаточно списка карточек?
