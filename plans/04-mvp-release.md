# Этап 04. Релиз MVP

## Цель

Довести MVP до публичного релиза в Telegram: тестирование, полировка UX, production-инфраструктура, публикация в @BotFather.

## Зависимости

- Этапы 00–03.

## Скоуп

### 1. Production-инфраструктура

- Создать prod-проект Supabase (отдельный от dev).
- Прогнать все миграции.
- Настроить бэкапы, политику ротации логов.
- Production-домен с HTTPS для TMA.
- Раздельные `.env` для dev/prod, секреты — через GitHub Actions secrets / Vercel envs.
- Production Telegram-бот (отдельный от dev, чтобы не пересекаться при тестировании).

### 2. Качество и стабильность

- **Sentry и продуктовая аналитика в MVP не подключаем** — добавим post-MVP.
- E2E-тест happy-path (Playwright) — создание желания, бронь слота от другого аккаунта.
- Smoke-тесты Edge Functions.
- Минимальное логирование ошибок Edge Functions через нативные логи Supabase.
- **RLS до релиза — ручная проверка** ключевых политик (auth, wishes, slots), особенно «скрытие слотов от автора». Полноценный автоматический test suite на RLS откладывается до выхода из беты (см. §8).

### 3. Полировка UX

- Аудит всех экранов: загрузочные состояния, пустые состояния (empty states), состояния ошибок.
- Поведение при отсутствии сети.
- Анимации переходов (плавность Mini App).
- Корректная работа в светлой и тёмной темах Telegram.
- Корректная работа на iOS и Android клиентах Telegram (часто отличается поведение `BackButton`/`MainButton`).
- Проверка на маленьких экранах (iPhone SE) и больших (iPad mini в Telegram).

### 4. Контент и тексты

- Финальная вычитка всех текстов.
- Описание для @BotFather (about, description, picture).
- Иконка бота.
- Превью-картинка Mini App.
- (Опционально) Простая landing-страница с описанием — для клика «Открыть» из @BotFather.

### 5. Юридика и приватность

- Privacy Policy (минимальная, как требование Telegram при публикации Mini App).
- Terms of Use (минимальные).
- Согласие на обработку Telegram-данных при первом входе (если требуется юрисдикцией).

### 6. Публикация

- Зарегистрировать бота в публичной экосистеме Telegram (если решим).
- Подключить Mini App через `@BotFather` → `Bot Settings` → `Configure Mini App`.
- Шаринг: убедиться, что `t.me/<bot>?startapp=...` deep-links работают и открывают нужные экраны.

### 7. Обратная связь

- Канал для багов: например, форма «Сообщить о проблеме» в профиле, отправляющая сообщение через бота в админ-чат.

### 8. Выход из беты в широкий релиз (exit criteria)

Что должно быть сделано **после беты, до публичного анонса**:

- Автоматизированный RLS test suite (Vitest + `@supabase/supabase-js`): владелец/не-владелец/анон по всем критичным таблицам, отдельно «скрытые от автора» инварианты для slots/comments.
- Закрыты P0/P1 баги из беты.
- Подключён Sentry (минимум).

## Вне скоупа

- Соцфункции, комментарии, события — всё это в post-MVP этапах 05+.
- Платная подписка / монетизация.
- Расширение на другие платформы.

## Ключевые решения

- **Dev и prod окружения полностью разделены** — два бота, два Supabase-проекта, два домена.
- **Прежде чем публиковать — закрытый бета-тест** в кругу друзей/коллег (минимум 2 недели).
- **Без Sentry/аналитики выходим осознанно** — рассчитываем на быстрый цикл бета-тестирования и канал обратной связи (см. §7). Подключение Sentry и продуктовой аналитики стоит первым в очереди post-MVP.

## Definition of Done

- Mini App доступен любому пользователю Telegram через бота.
- Все ключевые сценарии (signin → создать вишлист → поделиться → друг забронировал слот) работают на iOS и Android без ошибок.
- Есть рабочий канал получения обратной связи (см. §7) и налаженный процесс реакции на сообщения о багах.
