# Этап 13. Future Features (Backlog)

## Цель

Зафиксировать долгосрочные направления развития сервиса, которые не входят ни в MVP, ни в основной post-MVP, но которые имеет смысл держать в виду при проектировании архитектуры — чтобы не блокировать их в будущем.

## Зависимости

Все основные этапы (00–12) — каждая фича может зависеть от своих подсистем.

---

## 13.1. Secret Santa

**Идея:** игровой режим внутри списка участников — каждый получает одного «подопечного», которому втайне готовит подарок.

**Что нужно:**
- Сущность `secret_santa_games`: участники, дата проведения, бюджет.
- Алгоритм случайного парного назначения с гарантией отсутствия само-выбора.
- Скрытый канал коммуникации между «сантой» и его подопечным (без раскрытия личности).
- Возможность взять идеи из вишлиста подопечного.

**Зависит от:** этапов 02 (вишлисты), 06 (комментарии — для скрытого канала), 10 (бот для уведомлений).

---

## 13.2. AI-ассистент: предложение идей подарков

**Идея:** на основе лайков, репостов, истории взаимодействий — модель предлагает «что подарить» конкретному человеку.

**Что нужно:**
- Сбор сигналов (лайки/репосты/категории желаний).
- Эмбеддинги интересов пользователя.
- Векторное хранилище (например, `pgvector` в Supabase).
- LLM-запросы (через провайдера — OpenAI/Anthropic/локальный).
- UI «Идеи для подарка @user» с фильтром по бюджету.

**Зависит от:** этапов 05 (соц-функции), 02 (вишлисты).

**Риски:** privacy (не «утечь» интимные предпочтения), стоимость инфраструктуры.

---

## 13.3. Геймификация: достижения и бейджи

**Идея:** мотивировать активность через систему бейджей («Скинулся 10 раз», «Подарил коллекционеру», «Создал вишлист на 3 события»).

**Что нужно:**
- Таблица `achievements` + правила выдачи (триггеры на действия).
- UI бейджей в профиле.
- Опционально: лидерборды среди друзей.

**Зависит от:** этапов 03 (слоты), 05 (соц-функции).

**Риски:** перегеймизация может оттолкнуть «спокойную» аудиторию. Нужен опт-аут.

---

## 13.4. Календарь — синхронизация с системными календарями

**Идея:** события из этапа 07 синхронизируются в Google Calendar / Apple Calendar пользователя.

**Что нужно:**
- iCal-фид по уникальной ссылке (`/cal/<token>.ics`).
- Поддержка обновлений и удалений.
- Опционально: двусторонняя синхронизация через OAuth (сложнее).

**Зависит от:** этапа 07 (события).

**Риски:** маленькая ценность для большинства пользователей, лучше делать после явного запроса.

---

## 13.5. Парсинг ссылок (OG/JSON-LD)

**Идея:** при вставке ссылки на товар автоматически подтягивать заголовок, фото, цену.

**Что нужно:**
- Edge Function-парсер с whitelistом доменов (для борьбы со спамом и фишингом).
- Кэш парсинга в БД.

**Зависит от:** этапа 02.

---

## 13.6. Импорт/Экспорт вишлиста

**Идея:**
- Экспорт в PDF / iCal / простой текст.
- Импорт из других сервисов (Wishlistr, Amazon Wishlist) — если есть смысл.

---

## 13.7. Монетизация (далеко в будущем)

Возможные модели — фиксируем как варианты, не обещаем:
- Бесплатно базово, премиум: больше списков, расширенная аналитика «что дарили мне», красивые темы.
- Платные «события» с большим числом участников.
- Без рекламы (никогда — выглядит чужеродно для подарочного сервиса).

**Принцип:** платными становятся только «уровни сверху», базовая социальная функциональность всегда бесплатна.

---

## Принципы работы с backlog

- Не реализуем «впрок».
- Перед взятием в работу — короткий discovery (1–2 интервью с пользователями).
- Проверяем, не ломает ли фича базовый принцип «координатор без денег внутри».
