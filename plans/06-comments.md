# Этап 06. Скрытые комментарии под желаниями

## Цель

Добавить ветку обсуждения под каждым желанием, **полностью скрытую от автора желания**, чтобы друзья могли координировать выбор подарка прозрачно для всех, кроме получателя.

## Зависимости

- Этап 05 (соц-функции — профили, подписки, аватары / отображение авторов).

## Скоуп

### 1. Модель данных

Таблица `public.wish_comments`:

- `id` (`uuid`, PK)
- `wish_id` (`uuid`, FK → `wishes.id`, on delete cascade)
- `author_id` (`uuid`, FK → `profiles.id`)
- `parent_id` (`uuid`, nullable, FK → `wish_comments.id`) — для тредов первого уровня
- `body` (`text`, 1..2000)
- `is_deleted` (`boolean`, default false) — soft delete
- `created_at`, `updated_at`

### 2. RLS — критическая часть

- **SELECT:** все авторизованные **кроме автора** желания (`auth.uid() != owner_id_of(wish_id)`).
- **INSERT:** любой авторизованный, кроме автора желания (автор не может комментировать «у себя»).
- **UPDATE/DELETE:** только сам автор комментария.

> ⚠️ Так же, как со слотами — это должно работать **на уровне БД**, а не UI.

### 3. UI

- Под карточкой желания (для не-автора) — секция «Обсуждение».
- Список комментариев, форма ответа, поддержка тредов 1 уровня.
- Аватары и юзернеймы.
- Возможность редактирования/удаления своего комментария.
- Маркеры «новых» комментариев с момента последнего просмотра.

> **Упоминания @username** (парсинг, ссылки в тексте, уведомления упомянутому) и **любая интеграция обсуждения с отдельным Telegram-чатом** вынесены из этого этапа — см. [`10-telegram-bot.md`](./10-telegram-bot.md); идеи «обсудить в TG вне приложения» как расширение продукта — [`13-future-features.md`](./13-future-features.md).

## Вне скоупа

- Упоминания и TG-слой вокруг комментариев (**этап 10** / backlog **13** — см. ссылки выше).
- Real-time появление новых комментариев (этап 11).
- Реакции на комментарии (отдельным backlog-айтемом).

## Ключевые решения

- **Скрытость от автора — на RLS.** Любая утечка через UI/REST должна считаться security-багом.
- **Soft delete** — иначе ломаются треды (если удалить родителя, потеряются ответы).
- **Один уровень тредов** — для простоты UX. Глубокие иерархии не нужны.

## Definition of Done

- Не-автор видит и оставляет комментарии под чужим желанием.
- Автор желания **никаким способом** не видит комментарии (UI / REST / Edge Function).
- Можно отвечать на комментарий (1 уровень тредов).

## Открытые вопросы

- Нужно ли счётчик новых комментариев показывать самому автору? (По концепту — нет, иначе он понимает, что что-то происходит.)
- Реакции на комментарии — нужны или избыточны?
- Лимит на длину/частоту комментариев (анти-спам).
