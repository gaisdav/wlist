# Этап 12. Расширение на веб-сайт и React Native

## Цель

Использовать заранее заложенную моно-репо архитектуру и переиспользуемые пакеты (`core`, `api`) для запуска публичного веб-сайта и (опционально) мобильного приложения на React Native, минимизируя дублирование кода.

## Зависимости

- Все предыдущие этапы (особенно 00 — фундамент моно-репо).

## Скоуп

### 1. Аудит переиспользуемого кода

- Проверить, что `packages/core` действительно платформо-агностичен (нет импортов DOM, нет привязки к `@telegram-apps/sdk`).
- Вынести Telegram-специфику (`BackButton`, `MainButton`, `initData`) в адаптер `packages/platform-tma`.
- Создать аналогичные адаптеры:
  - `packages/platform-web` — для веб-сайта.
  - `packages/platform-mobile` — для RN.

### 2. Веб-сайт

Новое приложение `apps/web`:

- React + Vite (или Next.js, если нужна SEO/SSR — будет ясно к этапу архитектуры).
- Полноценная авторизация: Telegram Login Widget + (по мере необходимости) email/phone через Supabase Auth.
- Экспортирует те же бизнес-сценарии, что и TMA.
- Отдельный UI-слой `packages/ui-web` — компоненты, заточенные под десктоп и мобильный браузер.
- Шеринг ссылок (`/g/<slug>` гостевой доступ) технически уже на этом домене.
- SEO для публичных вишлистов / лендинг.

### 3. React Native (опционально)

Новое приложение `apps/mobile`:

- Expo + React Native.
- Авторизация: Telegram OAuth / email-phone.
- UI-слой `packages/ui-mobile`.
- Push-уведомления (FCM/APNs) — параллель с Telegram-ботом.
- Глубокие ссылки (universal links / app links).

### 4. Универсальный роутинг

- Решение по роутингу разное для каждой платформы:
  - TMA: что-то лёгкое (внутренний роутер с поддержкой `BackButton`).
  - Web: TanStack Router / React Router / Next.js routing.
  - Mobile: Expo Router / React Navigation.
- В `packages/core` — описание именованных маршрутов и их параметров (без рендера), каждая платформа реализует своё.

### 5. Тестирование на разных платформах

- Базовый набор E2E (Playwright для веба, Detox для RN).
- Отдельный CI-pipeline на каждую платформу.

## Вне скоупа

- Полная фичепарность: на запуске не обязаны быть все фичи всех этапов 05–11. Решаем приоритеты на старте этапа.

## Ключевые решения

- **Один источник правды для бизнес-логики** (`packages/core`). UI и платформа подменяемы.
- **Разные UI-пакеты на платформу** — попытка сделать один универсальный UI-кит обычно проигрывает по UX.
- **TanStack Query общий** для всех платформ — он работает и в React, и в React Native.
- **Telegram Login Widget на веб-сайте** даёт ту же идентичность пользователя — таблица `profiles` остаётся неизменной.

## Definition of Done

- Веб-сайт работает с тем же бэкендом, что и TMA, и поддерживает базовые сценарии (вишлисты, слоты).
- Гостевые ссылки `/g/<slug>` живут на веб-сайте.
- Авторизованный через TMA пользователь — тот же пользователь, что зашёл через Telegram Login на веб-сайте.
- (Если делаем) Mobile-приложение проходит ревью маркетов.

## Открытые вопросы

- React Native — нужен ли вообще, если мобильный браузер закрывает кейсы?
- Push-уведомления в RN — параллельно с Telegram или вместо?
