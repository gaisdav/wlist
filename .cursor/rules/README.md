# Cursor Rules для wlist

Эти правила автоматически применяются Cursor при работе над проектом — они задают принципы, которым агент должен следовать без напоминаний.

## Принципы написания правил

- **Кратко.** Каждое правило ≤ ~80 строк, одно — про один аспект.
- **Конкретно.** Примеры BAD/GOOD, а не общие слова.
- **Без дублирования архитектурного документа.** Правила ссылаются на [`../../docs/architecture.md`](../../docs/architecture.md) для подробностей. Сюда выносим только то, что агент должен помнить «по умолчанию».
- **Always-rules только для критичного.** Только три правила (`00`, `01`, `07`) применяются всегда. Остальные триггерятся по `globs` — это снижает шум контекста.

## Как добавить новое правило

1. Определи скоуп: всегда, или по `globs`.
2. Создай `NN-name.mdc` (нумерация для порядка отображения).
3. Frontmatter: `description`, `globs` (или `alwaysApply: true`).
4. Контент: правила, примеры, ссылки на источники правды через `mdc:путь`.
5. Обнови эту таблицу.

## Альтернатива: skills

Для одноразовых рутинных задач можно завести **skills** (триггерные `SKILL.md`), которые читаются по совпадению описания с запросом. Например, «создать новый сервис в `core`» или «добавить новую Edge Function». Сейчас таких нет — заводим по мере необходимости.
